Here are test ideas for the document upload feature, categorized by the requested quality characteristics.

### Functionality

* **Valid Uploads:** Upload valid PDF, DOCX, and TXT files ranging from 1KB to exactly 20.0MB to ensure they complete successfully.
* **Format Rejection:** Attempt to upload unsupported formats (e.g., `.xlsx`, `.png`, `.rtf`) and verify they are rejected with a clear error message.
* **Size Limits:** Attempt to upload files slightly over the limit (e.g., 20.1MB) and well over the limit (e.g., 50MB) to ensure they are blocked and handled gracefully.
* **Progress Indication:** Throttle the network speed to simulate a slow connection and verify the progress indicator accurately updates from 0% to 100% without freezing or jumping erratically.
* **Interrupted Uploads:** Cancel an upload mid-progress, or disconnect the network, and verify the system recovers cleanly without creating a ghost file or locking the UI.
* **Audit Logging:** Verify that both successful uploads and intentional failures (e.g., blocked due to size or format) are accurately recorded in the auditing feature.

### Data Integrity

* **File Corruption Check:** Download an uploaded file and compare its checksum/hash against the original local file to ensure no data loss or corruption occurred during transmission or storage.
* **Special Characters:** Upload files with long names, special characters (e.g., `!@#$%^&()_+.pdf`), and non-Latin scripts to ensure the database and file system store and display the names accurately.
* **Zero-Byte Files:** Attempt to upload empty (0-byte) PDF, DOCX, and TXT files to see if the system handles them without crashing or corrupting the storage index.
* **Audit Trail Accuracy:** Verify the audit report captures the exact file name, timestamp, file size, and uploader ID without truncation or data mismatch.

### Security

* **Initial Access Control (Authorization):** Log in as a different user (e.g., another paralegal, a lawyer, or a standard admin) and attempt to access, view, or download the uploaded document to ensure strict isolation.
* **Direct Object Reference (IDOR):** Attempt to access the uploaded file directly via its URL or API endpoint while unauthenticated, or while logged in as a different user.
* **Extension Spoofing:** Rename a malicious executable (e.g., `malware.exe`) to `malware.pdf` and attempt to upload it to verify if the system checks the actual MIME type/file signature rather than just the extension.
* **Malicious Payloads:** Upload DOCX or PDF files containing embedded macros or known test-virus signatures (like EICAR) to verify backend antivirus scanning (if applicable to the environment).
* **Audit Log Tampering:** Attempt to modify, delete, or obscure the audit log entries as the uploading user to ensure the audit trail is immutable.
* **Rate Limiting / DoS:** Rapidly send upload requests via an automated script to ensure the endpoint has rate limiting and cannot be overwhelmed, preventing a Denial of Service.
